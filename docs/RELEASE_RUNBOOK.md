# Release procedure

1. Review PUBLIC_RELEASE_READINESS.md and the current beta scope. Complete the required release checks, document outstanding field-validation limits, and review new tracked contents for private material. The public repository has already been separated from excluded private history; do not import that history. Automated path checks alone cannot prove a clean history.
2. Confirm VERSION, both C# project versions, sensor version and Python version match. Update friendly release text, manuals and release notes. Commit and review the exact source.
3. Run the **Build Windows release candidate** workflow manually for a candidate, or push a matching numeric `vMAJOR.MINOR.PATCH` tag after acceptance. The workflow uses a fresh Windows Server runner, pinned actions, Python/SDK versions, the bundled-runtime checksums, tests and NuGet vulnerability checks. Server CI does not count as a clean Windows 11 player machine.
4. Download the workflow artifact. It contains Setup, the verified portable ZIP, SHA256SUMS.txt, BUILD_INFO.json, LICENSE and release notes. The artifact ZIP is a maintainer container; users download its individual Setup/portable files from Releases. The workflow cannot publish or change visibility and has contents:read only.
5. Test the exact assets on a clean Windows 11 standard-user account, without development runtimes. Exercise first-run missing-game/logging states, paths with spaces/non-ASCII names, shortcuts, repeated launch, updates/recovery, and uninstall with external data preservation. Record pass/fail/not-exercised and source hash in the validation ledger.
6. Once the tested release is approved for publication, create a GitHub prerelease titled **GhostData — Phantom · Beta 1**, tagged with its numeric version. Upload the exact tested Setup and `GhostData-win-x64.zip`, checksums and build information. Do not rename the portable ZIP: the updater requires that name and GitHub's SHA-256 asset digest. State clearly that the release is unsigned and list unresolved beta limitations.
7. Check an unauthenticated installer download, hashes and launch. Test UPDATE from an older eligible installed build against the published beta, including apply-on-exit and history preservation. Existing older stable-only clients will not offer a prerelease; install the beta manually once. Only advertise public update success after exercising it.
8. Add the direct release download to the website and README, refresh the screenshot/version labels and remove the pending-download notice. Keep the license, privacy and support links visible.

Reproducible here means a documented repeatable recipe; byte-identical output is not claimed because compiler/installer timestamps and runner images can vary. BUILD_INFO records the exact source and workflow run. Inno Setup is supplied by the Windows runner image; bundled third-party notices are collected from the exact restored packages.
